# 班级成员管理系统需求分析文档

> 版本：v2.0（优化版）  
> 技术栈约定：Vue 3 + Spring Boot 3 + MySQL 8（Navicat 15 客户端）+ Java 19 + Maven 3.6.1 + IntelliJ IDEA 2022.3.2 Ultimate

## 1 引言

### 1.1 文档目的

本文档为**班级成员管理系统**的专属需求分析文档，用于明确系统开发目标、核心功能需求、使用场景、运行要求、业务规则及验收标准。本系统专为班级班长独立使用，无教师、班委其他管理员及普通同学登录操作入口，仅服务于班长日常班级人员统计、名单核对、人员筛查等班级管理工作，解决传统人工核对名单效率低、易出错、流程繁琐的问题，全面简化班级人员管理相关事务，为系统开发、功能迭代、落地使用提供完整、清晰的需求依据。

### 1.2 项目背景

目前班级总人数初始为 36 人（含班长本人），日常无频繁人员变动。班级管理中存在大量人员统计核对场景，例如活动抽签名单核对、志愿活动报名统计、讲座参与人员筛查、作业提交人员核对、考勤人员汇总等。

当前班长依赖第三方小程序、人工对照班级名单逐一核查的方式开展工作，存在明显弊端：第三方工具仅能完成报名、抽签、签到等基础操作，无法自动筛选未参与人员；人工逐一对账耗时费力、极易出现遗漏和错误；各类人员数据无统一留存渠道，历史记录难以追溯。为彻底解决上述问题，提升班级管理效率、降低工作成本，特开发本专属班级成员管理系统。

### 1.3 系统适用范围

- **使用人员**：仅限本班班长 1 人，无其他用户权限，班级其余同学无需注册、登录、操作系统，全程被动数据匹配。
- **适用场景**：班级各类人员核对、名单筛查、数据统计、记录留存等日常管理工作，包含但不限于活动抽签核对、报名统计、作业考勤、任务分配统计等场景。
- **人员范围**：初始 36 人班级成员名单作为系统基准数据；默认锁定，仅在班长主动解锁时可微调（见 §5.2）。

### 1.4 术语定义

| 术语 | 含义 |
|------|------|
| 基准名单 | 系统内已确认并锁定的本班成员名单，是所有比对的唯一标准 |
| 粘贴名单 | 班长从第三方工具导出/复制后粘贴进系统的临时姓名文本 |
| 已参与 | 粘贴名单与基准名单交集中的本班成员 |
| 未参与 | 在基准名单中、但未出现在粘贴名单中的成员 |
| 无效/异常 | 粘贴名单中不在基准名单内的内容，或空白、乱码、纯符号、明显无法解析的条目 |
| 去重 | 同一姓名在粘贴名单中出现多次时，仅计一次 |
| 长期任务 | 需要按期反复核对的工作（如青年大学习、德育打卡） |
| 核对记录 | 某一次名单比对的完整快照（含时间、结果、人数） |

## 2 总体概述

### 2.1 系统定位

本系统是**班长专属单人操作、班级人员数据自动匹配筛查**的轻量化管理工具，无需多人交互、无需完整账号注册体系，核心定位为「替代人工名单核对，一键筛查异常人员、未参与人员，自动化完成班级人员统计工作」，聚焦解决班长日常最繁琐的名单核对痛点，操作简单、功能精准、贴合班级实际工作。

系统形态为 **Web 应用**（浏览器访问），不是原生 App。

### 2.2 核心设计原则

- **极简操作**：所有功能一键触发、无需复杂配置，适配日常快速办公场景，降低班长操作成本。
- **精准匹配**：基于已锁定的基准名单为标准，在姓名全称规范化后进行精确比对，杜绝人工核对失误。
- **场景适配**：完全贴合高中/大学班级日常管理场景，针对性解决抽签、报名、考勤、作业等高频核对问题。
- **数据留存**：自动保存每次核对记录（结果快照），支持历史数据查询、追溯，方便后续班级工作复盘。
- **专属独占**：系统仅班长可操作，无其他用户权限；默认仅本机可访问，降低信息泄露风险。
- **结果可解释**：无效/异常内容不得静默丢弃，须在结果中可见，便于班长发现粘贴源数据问题。

### 2.3 整体业务流程

1. **初始化**：导入固定班级名单 → 预览核对 → 确认后锁定基准数据。  
2. **日常核对**：班长将第三方工具导出/复制的报名名单、抽签名单、签到名单、作业提交名单等批量文本粘贴至系统输入框。  
3. **自动筛查**：系统以基准名单为标准，完成解析、规范化、去重、比对，输出**已参与人员、未参与人员、无效/异常内容**三类结果及对应人数。  
4. **后续动作**：班长根据结果开展提醒、通知、登记等工作；系统自动保存本次核对记录，支持导出。

### 2.4 系统边界（明确不做什么）

- **不开发**抽签、报名、签到等交互业务功能；只做粘贴结果之后的**数据筛查、统计、记录、导出**。
- **不生成**随机数、不管理抽签过程、不代替第三方工具采集数据。
- **不提供**同学端、教师端、多角色后台；不提供完整注册/登录账号体系（访问控制见 §4.1）。
- **不管理**成绩、评优、缴费等与「人员名单核对」无关的班级事务。

## 3 功能详细需求

本系统所有功能均为班长单人操作，核心分为**基础数据模块、核心名单筛查模块、日常管理拓展模块、数据记录与导出模块**四大模块。

### 3.1 基础数据管理模块（核心基准）

该模块为系统所有功能的基础，提前录入班级人员数据，确认后默认长期作为比对基准。

#### 3.1.1 班级基准名单初始化

- 支持**批量导入**：一人一行，或逗号/顿号/空格/制表符分隔；支持从 Excel 复制粘贴。
- 支持**手动录入/核对**：列表内可单条添加、编辑（在解锁状态下）。
- 导入后进入**确认页**：显示导入人数、完整姓名列表、重复姓名提示；班长点击「确认并锁定」后方可作为基准。
- 确认后名单**默认锁定**，防止误删、误改；解锁修改流程见 §5.2。
- 建议字段：姓名（必填）、学号（可选，用于班内重名时辅助识别）、排序号。

#### 3.1.2 名单预览功能

- 班长可随时查看系统内存储的完整基准名单（含人数统计）。
- 锁定状态下为只读；解锁状态下可编辑，保存时需二次确认。

#### 3.1.3 基准变更影响说明

- 解锁修改并保存后，**后续**所有比对以新基准为准。
- **历史核对记录**仍按当时生成的快照展示，不随基准变更而改写，保证复盘可信。

### 3.2 核心名单智能筛查模块（核心痛点功能）

针对抽签核对、名单比对痛点，覆盖全部班级人员核对场景。

#### 3.2.1 批量名单一键比对筛查（核心功能）

- **操作方式**：班长在输入框粘贴任意来源的批量名单（微信抽签名单、活动报名名单、签到名单、作业提交名单、志愿报名名单等纯文本姓名列表）。
- **解析与规范化（系统自动执行）**：
  - 按换行、逗号、英文逗号、顿号、分号、制表符、空格等切分条目；
  - 去除首尾空白；全角字符转半角；
  - 去除行首序号前缀（如 `1.` `1、` `1)` `1）` `01` 等）；
  - 忽略空行、纯符号、无法构成姓名的碎片。
- **自动匹配规则**：
  - 以规范化后的基准名单为标准，对规范化后的粘贴条目做**姓名全称精确匹配**；
  - **已参与**：粘贴名单 ∩ 基准名单；
  - **未参与**：基准名单 − 粘贴名单；
  - **无效/异常**：粘贴名单中不在基准名单内的条目（含过滤掉的乱码/符号等，以原始展示形式列出）。
- **结果展示**：页面分栏展示三类内容，并自动统计人数，例如：
  - 已参与 30 人
  - 未参与 6 人
  - 无效/异常 2 条
  - 去重 1 人（若有）
- **解析预览**（建议实现）：并排显示「原始粘贴文本 / 解析后有效姓名 / 被剔除或无效项」，避免班长误以为粘贴完整。
- **适配场景**：讲座抽签未参与核对、活动报名缺人核对、作业未交统计、课堂签到缺勤统计等。

#### 3.2.2 重复名单自动去重

- 系统识别粘贴名单中的重复姓名（规范化后相同），统计时每人只计一次。
- 结果中展示去重后的有效名单，并提示本次**检测到的重复人数**（或重复次数）。
- 去重仅影响本次统计，不修改基准名单。

#### 3.2.3 无效人员/异常内容过滤

- 粘贴名单中存在**非本班人员姓名、空白、乱码、符号**等内容时，不计入「已参与」。
- **不得静默丢弃**：须在结果「无效/异常」栏展示，便于班长核对源数据。
- 无效条目仅存于本次核对记录（及导出文件），不写入基准名单。

#### 3.2.4 姓名匹配约定

| 项目 | 约定 |
|------|------|
| 默认匹配键 | 规范化后的**姓名全称**精确匹配 |
| 规范化 | 去空白、全半角统一、去常见序号前缀 |
| 重名处理 | 若班内存在重名，仅凭姓名无法 100% 区分；此时建议启用可选「学号」字段：粘贴内容同时含姓名与学号时优先用学号匹配；否则同名条目按同一人处理并在结果中标注「存在重名」提示 |
| 不做的事 | 不做模糊纠错（如「张山」自动改成「张三」），避免误匹配；无法匹配的进入无效栏，由班长人工判断 |

### 3.3 班级日常管理拓展功能模块

#### 3.3.1 人员随机任务分配辅助（核对辅助，非抽签）

- **系统不做抽签**，不生成随机结果。
- 班级通过**外部工具**完成抽签后，将抽签结果粘贴至系统，系统快速核对：
  - 已抽中/已在名单中的人员
  - 未出现的人员（是否需关注由班长判断）
- 支持**手动标记任务负责人/备注**（在核对记录或任务下），方便统计任务分配覆盖情况，避免重复分配、遗漏分配。
- 标记字段示例：负责人姓名、任务说明、备注；标记不改变「已参与/未参与」的比对结果。

#### 3.3.2 单项任务全员统计登记（长期任务按期核对）

- 适用于德育打卡、青年大学习、班级材料提交、回执单上交等**常态化、按期重复**的工作。
- 数据模型区分两层：
  - **长期任务（Task）**：如「青年大学习」；
  - **核对记录（CheckRecord）**：该任务下每一期的一次粘贴核对结果。
- 班长可为长期任务批量粘贴**每期**提交名单，系统自动每期筛查未提交人员，无需重复人工对账。
- 历史页支持按长期任务筛选，查看各期未参与情况。

#### 3.3.3 自定义人员分组统计

- 班长可手动维护分组（如卫生小组、学习小组、活动小组），将基准名单成员划分到一个或多个分组。
- 分组名单变更需在基准名单解锁或单独的「分组管理」中维护（分组管理本身不修改基准名单内容）。
- 任意名单核对结果支持**按分组二次筛查/分块展示**，例如单独查看「第 3 卫生小组」未参与人员。
- 分组仅用于统计视图，不改变全局比对逻辑。

### 3.4 数据记录与导出模块

#### 3.4.1 历史记录自动留存

- 系统自动保存每一次核对任务的历史记录，包含：
  - 任务名称（可自定义，如「9月20日讲座抽签核对」）
  - 所属长期任务（可选）
  - 核对时间
  - 粘贴原文（可选保存，便于追溯）
  - 已参与人员、未参与人员、无效/异常内容
  - 已参与人数、未参与人数、去重人数、无效条数
- 所有记录默认永久留存，支持按名称、时间、长期任务查询回溯。
- **人员结果一经生成即为只读快照**；后续基准名单调整不影响历史记录中的名单内容。

#### 3.4.2 名单结果导出功能

- 所有筛查、统计结果支持一键导出，格式至少包括：
  - **Excel（.xlsx）**：便于群发、打印、二次统计；
  - **文本/CSV（.txt 或 .csv）**：便于粘贴到微信等场景。
- 导出内容与页面结果一致：任务名称、时间、三类名单及人数、去重/无效统计。
- 导出文件名建议包含任务名称与日期。

#### 3.4.3 记录删除与编辑

| 操作 | 是否允许 | 说明 |
|------|----------|------|
| 编辑任务名称/备注 | 允许 | 不影响人员结果 |
| 删除历史记录 | 允许 | 需二次确认 |
| 修改已参与/未参与/无效名单 | **不允许** | 保证复盘数据可信；如需重新核对，应新建一次核对 |
| 编辑基准名单 | 仅解锁后允许 | 见 §5.2；不影响历史快照 |

#### 3.4.4 数据备份（建议实现）

- 支持一键导出全量数据（SQL 或 JSON：基准名单、分组、长期任务、核对记录）。
- 支持导入备份文件进行恢复（至少覆盖本系统导出的格式）。
- 用于误删防护与换机迁移。

## 4 非功能需求

### 4.1 权限与访问控制需求

- 系统**无注册、无完整登录账号体系**，不提供同学/教师多角色入口。
- **默认部署约束**：后端服务默认绑定 `127.0.0.1`，仅本机浏览器访问，杜绝同网段误访问。
- **可选局域网访问**：班长需在手机等设备访问时，可显式配置监听地址，并启用**极简访问口令**（由环境变量/配置文件设定，非注册体系）；未通过口令不得进入系统。
- 基准名单默认锁定，修改需解锁 + 二次确认（见 §4.1 与 §5.2），防止基准数据错乱。
- 所有班级数据仅本地数据库留存，不主动对外提供公开 API 文档入口以外的匿名访问。

### 4.2 性能需求

- 响应速度快：粘贴名单后，**1 秒内**完成解析、比对、统计并展示结果（36 人规模应远低于 1 秒）。
- 容错性强：支持格式不规整、换行混乱、含空格/全角/序号的名单文本，系统按 §3.2.1 规则自动适配解析。
- 稳定性高：长期运行无崩溃、无数据丢失，历史记录稳定留存。

### 4.3 易用性需求

- 界面简洁直观，功能分区清晰，零基础可快速上手。
- 核心操作流程统一：**粘贴名单 → 一键筛查 → 查看结果 → 复制/导出/留存记录**。
- 结果展示清晰：人员名单整齐排列，人数一目了然；未参与名单支持**一键复制**。
- 提供解析预览或无效项列表，降低「粘贴错了却不知道」的风险。

### 4.4 兼容性需求

- 系统形态为 **Web 应用**（非原生 App）。
- 支持电脑、手机浏览器访问；界面采用响应式布局，适配主流现代浏览器（Chrome / Edge / Safari 等）。
- 无需安装客户端软件；服务以可执行 jar 或开发模式在班长本机/授权环境运行。

### 4.5 可维护性与工程需求

- 前后端代码分离，仓库内包含完整可构建工程，可在 IntelliJ IDEA 2022.3.2 中直接打开开发。
- 后端提供清晰 REST API；前端通过 HTTP 调用。
- 关键业务（解析、比对、去重）具备单元测试。
- 配置（数据库连接、监听地址、访问口令）外置，不硬编码在源码中。

## 5 业务规则与约束

### 5.1 比对与统计规则

1. 所有名单比对在**规范化后按姓名全称精确匹配**（可选学号辅助，见 §3.2.4）。  
2. 统计口径：已参与 + 未参与 + 无效 = 解析后的粘贴条目与基准名单的对应关系说明中的计数基准（无效不计入已参与）。  
3. 去重仅作用于本次粘贴名单的有效本班姓名。  
4. 系统仅做**数据筛查、统计、记录、导出**，不开发抽签、报名、签到等采集交互功能。

### 5.2 基准名单锁定与解锁

1. 初始化确认后，基准名单**默认锁定**。  
2. 班长可主动**解锁**，修改（增删改）后**重新锁定**；每次解锁/保存需二次确认。  
3. 人数不必恒为 36；文档中的 36 人为**初始规模**。解锁调整后以最新名单为后续比对基准。  
4. 历史核对记录不受解锁修改影响（快照只读）。  
5. 建议在解锁修改时留下简单操作日志（时间、修改人=班长、变更摘要）。

### 5.3 权限与范围约束

1. 无多用户交互场景，所有操作、数据仅归班长所有，无同学操作入口。  
2. 默认仅本机访问；开放局域网时必须配置访问口令。  
3. 数据不得通过公开无鉴权接口暴露在公网。

### 5.4 产品边界再强调

- 不实现随机抽签、报名收集、在线签到打卡等第三方已具备的采集能力。  
- 不把系统扩展为完整教务/班务 ERP；范围收敛在「名单核对与统计」。

### 6.1 建议数据模型（实现参考）

## 7 验收标准

### 7.1 功能验收

1. 可完成基准名单批量导入、确认锁定、只读预览；解锁修改需二次确认。  
2. 粘贴含重复、空格、全角、序号前缀的名单后，1 秒内返回**已参与 / 未参与 / 无效**三栏及人数。  
3. 去重人数、无效条数可见；无效内容不被静默丢弃。  
4. 历史记录可按名称/时间/长期任务查询；可改名/改备注/删除；**人员结果只读**。  
5. 长期任务支持多期核对记录。  
6. 自定义分组可维护，核对结果可按分组查看未参与人员。  
7. 结果可导出 xlsx 与 txt/csv；导出内容与页面一致。  
8. （建议）一键复制未参与名单。  
9. （建议）全量备份导出与恢复可用。

### 7.2 非功能验收

1. 默认仅 `127.0.0.1` 可访问；启用局域网访问时口令未通过则无法使用。  
2. 电脑 Chrome/Edge 与手机浏览器核心流程可操作（列表可读、按钮可点、结果可查看）。  
3. 工程可在 IntelliJ IDEA 2022.3.2 中打开，后端可运行，前端可 `npm run dev` 或随 jar 提供静态页。  
4. 解析、比对、去重存在自动化测试且通过。

### 7.3 明确不验收的功能

- 抽签/报名/签到采集流程  
- 多用户角色权限、注册登录  
- 成绩、考勤硬件对接等扩展班务

## 8 系统预期价值

本系统落地后，可将原本耗时数分钟的人工名单对账缩短至秒级自动完成，降低班级管理时间成本与人工失误率。通过历史快照留存、长期任务分期统计、分组筛查与导出能力，实现班级人员核对工作的标准化、可追溯化，让通知、提醒、督查等后续动作有据可依，切实减轻班长工作负担。
